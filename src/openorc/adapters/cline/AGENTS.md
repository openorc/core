# Cline Adapter Agent Context

## Boundary

Use the official pinned `@cline/sdk` / `ClineCore` public remote-session surface through the narrow Python backend/Node bridge. Do not reimplement Hub wire protocol, parse private Cline files, or mirror the entire SDK into OpenOrc. Consult current official Cline SDK documentation before source archaeology or live qualification; upgrade the qualified CLI/core/SDK baseline deliberately together, with affected remote-runtime checks.

## Sessions, authority, and working context

- Preserve exact Task-scoped Producer/Reviewer sessions and distinct working contexts. Initialize once through validated `session_ready`; never replace an established external identity because a send, Hub, or bridge failed.
- Cline-native PLAN/ACT construction mode realizes the authorized role workflow. Reviewer stays PLAN; Producer may ACT only for authorized checkout preparation, post-implementation-authorization work, and terminal checkout cleanup. Mode/working-directory changes use the qualified same-ID reconstruction with the raw existing messages; do not create another OpenOrc session or resend initialization.
- The caller owns durable Task/role/Connection routing, selected base/checkout identity, and workflow authority. Adapter construction resolves current safe role configuration and only the already-selected exact working context; runtime/provider IDs are opaque and Cline owns provider authentication and native settings.
- Never infer workflow acceptance, session loss, delivery, or completion from Cline bookkeeping status or optional telemetry. Confirm lost context using supported positive evidence, not missing events or an unavailable Hub.
- Native tool approval is Cline-owned. v1 auto-approves enabled tools, disables `ask_question`, and registers no OpenOrc interactive approval executor; do not set spawn-agent/team flags.

## Delivery, review, and telemetry

- Unknown send/reconstruction/interrupt outcomes require public-read reconciliation, not blind replay. Bridge/client disconnect may leave work completing Hub-side; restart may reset usage and require same-ID reconstruction.
- Hub-native run admission (`enqueue`, issue #321) is a distinct transport operation from `send`: admission is neither delivery nor execution, the acknowledged `runId` is transport evidence for later exact correlation (never a workflow decision), accepted failed runs may emit no terminal event, and an uncertain admission (a timeout, a transport loss, or an unproven SDK rejection — `enqueue` is in the unproven-effect classification set without latching the D6b effects, because its uncertainty is owned durably by the outstanding receipt) never authorizes a resend.
- Detached session establishment (issue #324): in regular mode the mandatory Producer/Reviewer initialization is one promptless `ClineCore.start()` (the v1 `interactive` bundle, no prompt) plus one `run.enqueue` admission of the composed canonical initialization verbatim — never a `send` and never a prompt-inside-`start` shortcut. The adapter implements the runtime-neutral detached capability (`allocate_detached_session`/`admit_detached_turn`, issue #348) whose neutral admission result carries the opaque turn reference; the capability stays optional beside the universal `AgentRuntimeAdapter` surface and never expands it; during the provisional window the adapter's own allocation registry is the only exact-session proof, and the durable construction-context resolver takes over after READY. A no-prompt session may carry a Cline `completed`/`endedAt` record before readiness: that bookkeeping is never session loss, never an end, and never a validated `session_ready`.
- The conversation read (issue #339): the adapter implements the runtime-neutral `SessionConversationReader` capability (`read_conversation`) as one pure observational `read_messages` read of the exact addressed session — the same durable construction-context exact-session discipline as the admission, no effect, no D6b latch, and a defensive projection into `ConversationMessage` records (the message's own `type`/`text` when string-typed, honestly unknown otherwise). It serves the authorized Owner-facing conversation read projection; the runtime owns the conversation and OpenOrc records no transcript.
- The detached-turn observation source (`hub_observation`, issue #348) owns the per-connection Hub attachment, the exact-session subscriptions, the bounded status-only `run.list` consultations, and — through the pure `hub_projection` interpretation layer — the native attribution semantics of which evidence proves or counters an admitted turn: the `run.started` `requestId` start-identity claim, the durable-log sequence ordering and stale-replay verdict, the `run.list` state-token meanings, and the terminal outcome/candidate extraction. It exposes only the runtime-neutral evidence envelopes and verdicts the settlement seam consumes; envelope/session identity is never synthesized, a terminal envelope without its own session identity is unattributable, and an uninterpretable status record fails closed instead of being silently dropped. The exact-session observation (issue #341) also subscribes the session's live event stream and — reusing the same D6c projection and E6 qualifying classification — delivers only content-free `TURN_ACTIVITY`/`TURN_USAGE` pulses plus the bounded neutral `consult_session_usage` reading (aggregate-scope-only, exact decimal, absent readings unknown); every kind, tool name, commentary, and payload detail stays behind this boundary. The terminal classification also exposes the neutral interrupted verdict (issue #342): the pinned SDK's R2b-qualified interruption finish reason (`SDK_INTERRUPTED_FINISH_REASON`, shared with the blocking-send path's `AgentRuntimeInterruptedTurnError` normalization) read kind-agnostically from the native terminal result is the ONLY positive interrupted-turn evidence — every other shape stays honestly non-interrupted. The D6b settlement outcome/refusal vocabulary (`ClineSettlementOutcome`/`ClineSettlementRefusal`) is a deliberate alias of the shared runtime-neutral `agent_runtime` types, so shared abort policy never imports this concrete module. A coordinated SDK upgrade modifies this package and `packages/cline-sdk-bridge/`; shared application, domain, and persistence changes require a genuinely new OpenOrc capability, never a transport revision.
- Planning REVIEW sends the exact canonical PlanRevision; PR REVIEW supplies canonical PR and reconciled head SHA to the existing Reviewer session. Formal result validation and workflow consequences remain outside the Cline backend. Do not demand a private Reviewer checkout or certify the Reviewer's tool inspection.
- Activity projections are explicitly read-only, Task/session-bound allowlists. Suppress reasoning, prompts, formal envelopes, tool/MCP inputs and outputs, raw errors, and credential-bearing data; only permitted completed assistant commentary and safe usage/status facts reach authorized clients. Usage is advisory and not evidence of success or continuity.
- The E6 qualifying-activity pulse (``subscribe_qualifying_activity``, issue #246) is the runtime-neutral derivative of the activity projection: the adapter owns the qualifying classification and exact external-session enforcement, and the consumer receives only a zero-argument pulse carrying no content. Vendor-specific activity vocabulary never crosses into shared application services.
- Connection `control_endpoint` is a validated `ws://`/`wss://` shape in safe config, never a credential or an assertion that its destination is safe. Deployment network isolation owns egress/SSRF protection.

Read `packages/cline-sdk-bridge/AGENTS.md` for bridge changes and services/domain guidance for workflow changes.
